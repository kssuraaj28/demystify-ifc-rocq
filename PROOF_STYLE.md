# Proof Style

- We use ssreflect freely.
- Use `Set Default Goal Selector "!"` for easier proof repair. Do not use the
  `all:` goal selector. Write the goal numbers explicitly.
- Have good discipline to handle autogenerated names. It is okay to `Unset
  SsrIdents` while discovering a new proof. Finished proofs should not have this.
- Do not use the `by`, `first`, or `last` ssr tacticals. `by` does too much; its
  terminating behaviour can be enforced by the system better (via the goal
  selector and strict subproofs settings above). Use `cycle` for `last first`.
  Use `[ t |..]` for `first t`, etc.
- Do not use `intro`; use `move` instead, for uniformity.
- Do not use `destruct`, use ssr `case`, for uniformity. Similarly use ssr `elim` instead of `induction`.
- All rewriting tactics are fine to use (ssreflect, normal, etc.). Normal rewrite can rewrite under binders.
- Try to wrap user-defined tactics by `assert_goals`, `ensure_goals`, or
  `harden`. 
  - Use `assert_goals` (hard throw) when a goal-count mismatch
   indicates a programmer error.
  - Use `ensure_goals` (soft failure) when the call
   site needs to backtrack on a mismatch.
  - Fall back to `harden` when you cannot assert a goal count. 
- You may have to prefix your tactic by `idtac;` to prevent eager evaluation
  (https://rocq-prover.zulipchat.com/#narrow/channel/237977-Rocq-users/topic/Weird.20bug/with/593251599).

# `cook`

`cook` is the project automation tactic, defined in `Tacs.v`. It runs
registered tactics over the focused goals until all goals are either solved or
all the tactics fail.

- `cook` runs to completion (no gas).
- `cook n` runs at most `n` outer iterations (gas). Goals are consumed in a dfs manner.
- `cook_step` runs one pass over the registered list on a single focused goal.
- `cook_step n` runs the `n`-th registered tactic.
- `curr_cookbook` is an ltac2 list of the currently registered tactics. To change, use 
    `Ltac2 Set curr_cookbook`. 
- Use `create_new_cookbook`, `append_tac`, `join_taclist`, etc. to manage cookbooks.
- Set `Ltac2 Set cook_debug := true.` to print a debugging trace.

`cook_step` normalizes the goal with `move=> *` before dispatching the
registered chain, and again on every produced subgoal after a successful
tactic. Contract for chain-step authors: you can assume `move=> *` was just
run on the goal you receive, and `move=> *` will run on every goal you
produce.

After running, all `cook*` notations apply `goal_hygiene` (revert +
reintroduce) to give clean, fresh hypothesis names.

## Cookbook tactics

Best practice: the description string passed to `append_tac` matches the
underlying lemma name, e.g. `append_tac 1 ltac1:(rewrite Forall_map)
"Forall_map" old`. Helps when reading debug output.

When a step boils down to "rewrite a normalization equality", prefer writing a
plain `Lemma` and registering `rewrite <lemma>`. For lemmas whose RHS is just
the `cbn`-normalized LHS, the `cbn_eq` Ltac2 notation builds the equality type
for you. It is preferable to use `rewrite -> <lemma> in *`.

### Cookbook re-Import

`Ltac2 Set` declarations replay on every `Import` of the file. Without care,
a file imported twice doubles the chain. Avoid this by following each
`#[local] Ltac2 mutable this_cookbook_ := create_new_cookbook.` with a
redundant `Ltac2 Set this_cookbook_ := create_new_cookbook.` reset:

```coq
#[local] Ltac2 mutable this_cookbook_ := create_new_cookbook.
Ltac2 Set this_cookbook_ := create_new_cookbook.
```

The reset is itself a `Set` and replays on Import, wiping any previously
accumulated chain before the registration `Set`s re-accumulate. The result
is idempotent under repeated `Import`.
